# ToolzNG within the NUN ecosystem

ToolzNG remains a local Windows diagnostic application. It is not a remote device-management agent, an iOS repair tool or a general plugin host. The NUN contracts are intended for structured exchange of policy metadata and diagnostic evidence; they do not broaden ToolzNG's device-access permissions.

## Alucard — bounded diagnostics

Scans, watchers, event history and report retention must stay within explicit time, memory and record-count bounds. On pressure, ToolzNG may stop optional sampling, shorten non-critical history or reject a new report. It must preserve the distinction between `Observed`, `Not found` and `Unknown`. An emergency UI state must never convert incomplete evidence into a positive result.

## Shanks — local-first by default

The current product is designed to work without an account, telemetry or cloud transfer. Do not add gossip or background network discovery to the diagnostic core. A future explicit export may synchronize redacted report metadata, but remote dashboards are eventually consistent and cannot command a device or override local Windows evidence.

## Nun — reports are records, not proof

The existing PulseVault is a bounded local event journal with rotation. Rotation is useful for resource control but means the journal is not immutable or a complete forensic archive. The report sidecar can detect later file changes; it does not prove that the underlying report was truthful or generated by a trusted device.

If a versioned NUN event envelope is emitted in a future adapter, include per-producer sequence numbers, monotonic timing and data classification. Redact hardware identifiers, full backup paths and other private fields before export.

## Ging Freecss — fixed, inspectable workflows

The current SAMBU-derived workflow invokes a small set of fixed diagnostic actions. Keep it declarative and allow-listed. Workflow documents may select known checks and presentation rules; they must not evaluate arbitrary scripts, load native extensions or silently change the device.

The five evidence states and score inputs should remain reviewable in code and tests. A clever scoring rule is not a substitute for a disclosed evidence model.

## Jinn — containment for future heavy work

The current diagnostic path should remain synchronous and bounded where practical. If expensive parsing or report generation is later moved to a worker, give it read-only input, a fixed queue, a timeout and minimal filesystem permissions. An untrusted worker must run out of process; an in-process callback is not a sandbox.

## Contract boundary

Klipot defines the shared capability and event schemas. ToolzNG's current integration with SAMBU is a native C adaptation of selected policy principles, not an embedded Python runtime or a dependency on the whole SAMBU package. There is no current Klipot event transport or plugin executor in ToolzNG; those remain future adapter work.

Safety-sensitive actions remain outside the tool's scope: no jailbreak, passcode bypass, Activation Lock bypass, backup-payload inspection, hidden device writes or automatic driver repair.
