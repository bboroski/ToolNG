# Duck Design Rules

**Норматив проекта:** 1.0.0  
**Применяется к:** ToolzNG, SAMBU Engine, пользовательскому интерфейсу, отчётам, CI и документации.  
**Статус:** обязательный стандарт для новых изменений. Открытые требования явно помечаются как roadmap.

Duck Design — инженерная дисциплина, а не декоративный набор правил. Утка — символ любознательности и координации независимых модулей, а не ограничение возможностей программы. Внешний лоск не должен опережать реальные возможности приложения.

## 1. Evidence before claims

Каждый диагностический вывод должен иметь источник сигнала, преобразование, критерий и ограничение.

- Windows-visible PnP-интерфейс с VID_05AC подтверждает видимость USB-интерфейса в Windows, но не полноценный pairing-сеанс iOS.
- Наличие Info.plist и Manifest.db / Manifest.plist подтверждает ожидаемую структуру папки, но не целостность, полноту, шифрование или восстановимость backup.
- Время изменения Info.plist — возраст маркера, а не актуальность всех данных резервной копии.
- LinkDNA на FNV-1a сравнивает локальный отпечаток Windows-visible сигналов. Это не серийный номер и не криптографическая идентичность.
- SHA-256 sidecar обнаруживает последующее изменение файла, но не доказывает истинность его содержимого.

Не расширяй смысл измерения ради более эффектного описания в UI, README или рекламе.

## 2. Unknown is not absent

Система различает три состояния:

1. **Observed** — проверка завершилась, источник доступен, сигнал подтверждён.
2. **Not found** — источник проверен, но ожидаемый сигнал не найден.
3. **Unknown** — источник недоступен, чтение завершилось ошибкой или проверка не завершена.

Незавершённое перечисление устройств не означает, что устройство отсутствует. Недоступный watcher не подтверждает стабильность USB. Ошибка чтения не превращается в зелёный результат.

## 3. SAMBU Quality Gate

Перед начислением баллов проверяется согласованность доказательств.

- Наличие устройства засчитывается только после успешного завершения сканирования.
- Число валидных backup-каталогов не может превышать число просмотренных.
- Маркер валиден только тогда, когда подтверждён хотя бы один каталог.
- Backup-маркеры засчитываются в readiness только тогда, когда проверены все обнаруженные каталоги.
- Частичный набор папок получает finding структуры, но не получает баллы за полную валидность маркеров.
- Период стабильности засчитывается только при активном USB watcher.
- Противоречивые счётчики и непроверенные предпосылки формируют quality flags и понижают confidence.

Текущие integrity flags:
- <code>DEVICE_WITHOUT_SCAN</code>
- <code>BACKUP_COUNTS_INCONSISTENT</code>
- <code>BACKUP_SET_INCOMPLETE</code>
- <code>STABILITY_WITHOUT_WATCH</code>

Readiness — объяснимая эвристика Windows-side подключения, а confidence — индикатор полноты и согласованности наблюдений. Ни одно из значений не является вероятностью аппаратной исправности телефона.

## 4. Fail-closed capabilities

Разрешения выдаются явно. Неизвестные операции и неизвестные значения origin всегда отклоняются.

| Операция | Правило |
|---|---|
| Локальное чтение | Internal или User |
| Windows PnP / service scan | Internal или User |
| Создание приватного отчёта | Только User |
| Экспорт отчёта | Только User |
| Буфер обмена | Только User |
| Изменение устройства | Всегда запрещено |
| Передача данных по сети | Всегда запрещена |
| Неизвестный operation / origin | Запрещено |

Никаких скрытых исправлений, автоматического удаления данных, неявной отправки, повышения привилегий или обхода механизмов защиты Apple.

## 5. Bounded by default

Любой журнал, очередь, буфер, кэш и повторная попытка имеют явную границу.

- SAMBU finding ledger: 32 уникальных кода.
- Recurrence window: 10 минут на монотонных часах.
- USB Pulse: фиксированная очередь наблюдений.
- PulseVault: ограниченный JSONL-файл с ротацией.
- Локальная история отчётов: до 32 файлов.
- Любая будущая фоновая задача обязана иметь отмену, таймаут, лимит памяти и верхнюю границу повторов.

Переполнение должно иметь определённое, детерминированное и протестированное поведение.

## 6. Local first, data minimal

Локальная работа — основная модель проекта. Приложение не требует аккаунта и не отправляет диагностические сведения на сервер.

- Не читать payload-файлы backup для простого structural audit.
- Не сохранять Hardware ID и полный путь к пользовательским данным в приватный отчёт.
- Не писать серийные номера, личные файлы и содержимое устройства в USB-журнал.
- Сеть и телеметрия не добавляются без отдельного решения, прозрачного согласия и выключенного по умолчанию состояния.
- Экспорт инициирует пользователь после просмотра содержимого.

## 7. Small core, clear layers

- SAMBU policy, evidence assessment и bounded ledger живут в переносимом C17 core.
- Windows SetupAPI, service control и device notifications принадлежат платформенному слою.
- Win32/GDI отвечает за представление, а не за диагностику.
- Экспорт не получает разрешения на изменение устройства.
- Машинные finding-коды стабильны; текст UI может локализоваться и не является API.
- Новая зависимость требует обоснования, оценки размера, лицензии, обновляемости и жизненного цикла.

Python-hosted SAMBU не выдаётся за нативный компонент ToolzNG. Host API, исходник-мост или scaffold не считаются завершённой интеграцией без работающего adapter.

## 8. Visual hierarchy

Базовая тема — графит с дозированными жёлтыми акцентами.

| Токен | Значение | Использование |
|---|---|---|
| Graphite | <code>#0D0D0D</code> | Основной фон |
| Surface | <code>#141414</code> | Шапка и боковая панель |
| Panel | <code>#1A1A1A</code> | Карточки |
| Duck Yellow | <code>#FFD600</code> | Ключевое действие и фокус |
| Deep Gold | <code>#BFA100</code> | Вторичный акцент |
| Primary Text | <code>#E6E6E6</code> | Основной текст |
| Muted Text | <code>#999999</code> | Вспомогательный текст |

Жёлтый не должен заливать каждый элемент. Информационный статус не кодируется одним цветом: добавь текст, значок или понятную форму. Не злоупотребляй декоративными рамками, свечением, градиентами и badges. Сохраняй стабильные отступы, группировку и понятную иерархию.

Относительно фона <code>#0D0D0D</code> контрастные отношения составляют ориентировочно 15.6:1 для <code>#E6E6E6</code>, 13.8:1 для <code>#FFD600</code> и 6.8:1 для <code>#999999</code>. Для обычного текста целевой минимум — 4.5:1.

## 9. Accessibility is functionality

Новые экраны и интерактивные элементы учитывают:

- Windows High Contrast и системные настройки отображения;
- Per-Monitor DPI и изменение масштаба без обрезки элементов;
- видимый keyboard focus, логичный Tab order и клавиатурные действия;
- UI Automation: программные имена, роли, состояния и доступность для вспомогательных технологий;
- текстовое описание значимых графических сигналов;
- понятный статус независимо от различения цветов.

Уже реализованы High Contrast, Per-Monitor DPI v2 и пользовательский zoom 80–160%. Полный UI Automation provider для саморисуемых элементов и полноценная клавиатурная навигация остаются задачами развития. Не отмечать их как готовые до реализации и тестирования.

## 10. Truthful previews

- Статические SVG-макеты прямо помечаются как <code>SAMPLE DATA</code>.
- Макет не называется скриншотом работающего приложения.
- Демо-устройство, значение readiness и статус не выдаются за реальное измерение.
- Превью соответствует текущим разделам, названиям и ограничениям UI.
- Изображение не заменяет тест, сборку и готовую реализацию.

## 11. Stable contracts

- Finding IDs — стабильный машинный интерфейс.
- Локализованные тексты и подсказки не являются ключами API.
- Отчётная схема версионируется и описывается.
- Additive-поля допускаются, пока не ломают существующих потребителей.
- Breaking change требует новой версии схемы и миграционных заметок.
- Смена engine version синхронизируется с UI, отчётами, README и интеграционной документацией.

## 12. Supply-chain and CI discipline

- GitHub Actions используют полный commit SHA, а не только изменяемый version tag.
- Обновления Actions проверяются и выполняются регулярно через Dependabot.
- CI имеет минимально необходимые permissions.
- CTest запускается на Windows и переносимых runner.
- Для поддерживаемого переносимого ядра включаются AddressSanitizer и UndefinedBehaviorSanitizer.
- Документационные ссылки и SVG проверяются автоматически.
- Секреты не выводятся в build-логи.

Полный SHA для Action должен ссылаться на проверенный upstream release. Не обновляй SHA механически без проверки источника и совместимости.

## 13. Change acceptance gate

Новое изменение не считается завершённым, пока:

1. Источник сигнала, разрешения и граница доступа описаны.
2. Поведение определено для успеха, отсутствия данных, ошибки и противоречия.
3. Есть позитивные, негативные и граничные тесты.
4. Пройдены CMake configure/build, CTest и документационный валидатор.
5. Windows-специфичный путь проверен Windows CI.
6. README, локальная справка и roadmap описывают одно и то же состояние.
7. Внешние зависимости проверены на актуальность и безопасность.
8. Пользователь может отличить выполненное действие от рекомендации или неизвестного результата.

## Definition of Done

Изменение соответствует Duck Design, если оно **полезно, доказуемо, ограничено, доступно, приватно по умолчанию и честно описано**. Эффектность допустима лишь после прохождения этих условий.
